# Night log — Epic A v2: aux command banks + fast settle (clean-room rebuild)

Date: 2026-06-11. Branch: `claude/aux-seq-v2` (off `main` @ `bbcadfe`, the
post-routing-fix baseline: WNS +0.275, async clock groups, LUTRAM FIFO,
84-MHz reset domain, AXI @ 131.25 MHz).

Implements `docs/command-bank-design.md` (carried onto this branch from
`claude/roadmap` together with `ROADMAP.md`). The sequencer was written
**clean-room from the design doc** — the prior RTL on `claude/roadmap` was not
read until the fresh implementation passed its testbench — then the two
designs were compared (section below) and the best ideas kept.

**Bottom line:** sequencer + override layer + datapath integration + firmware
+ host control are implemented and sim-verified, including a cycle-exact
proof that the `aux_seq_en=0` datapath is bit-identical to `main`'s. Build
results vs `main` are at the end.

## What was built

### `aux_command_sequencer.sv` (one module, 3 slots via generate loop)
- 3 independent slots → COPI cycles 32/33/34; 2 banks/slot (active+standby),
  64 entries/bank, 16-bit RHD commands.
- **Length bound to the bank**: per-bank `(loop_idx, end_idx)` registers,
  written through the same port (`wr_is_length` flag) — a bank swap atomically
  swaps program *and* length.
- Index starts at **0** on swap, wraps `end_idx → loop_idx`: `loop_idx > 0`
  gives a run-once preamble (config) + looping tail inside a single bank.
- Swap latches **only at a packet boundary** while streaming (immediately when
  idle, so the PS confirm handshake can't hang on a stopped stream);
  `bank_active` + per-slot indices exported for the confirm-before-reuse poll.
- **One-shot slot-3 injection** (runtime `READ/WRITE_REGISTER`): replaces slot
  3's command for exactly one packet and freezes that slot's index, so the
  loaded program plays on with no entry skipped.
- Storage: registered-read RAM → Vivado infers **BRAM (1.5 tiles)**. This is a
  deliberate divergence from the doc's "distributed RAM" default: the previous
  integration died of SLICEM/LUTRAM congestion around `fifo_bram_interface`
  (which now itself holds LUTRAM after the `main` routing fix), while ~138 of
  140 BRAM tiles idle. The 1-cycle synchronous read is free — the index
  updates at the packet boundary and the command serializes ~2500 clocks later
  (the design doc's "prefetch" slack).
- Power-on contents = `CONVERT(32+slot)`, length 0 → enabling an unprogrammed
  sequencer reproduces today's aux behavior exactly.

### `override_layer.sv`
- Operates **per-packet on the 3-slot command bundle** (not per-cycle): all
  trigger levels (software bits OR a selected `digital_in` pin) are sampled
  once at `packet_start` — the same instant `digital_in` is latched for the
  header — and the rewrite is combinational on those latched values, stable
  from header-echo time (state 2) through aux serialization (cycles 32-34).
- Amp fast settle (Reg 0 **D5**, datasheet-confirmed): on a level **edge**,
  slot 1's command is replaced with `0x80FE` (on) / `0x80DE` (off) for one
  packet (the non-D5 bits are the datasheet recommended values, identical to
  the firmware init blob). Any passing `WRITE(0,…)` from any slot gets D5
  forced to the live level.
- Reg-3 shadow: host owns `reg3_static[7:1]` (MUX load, tempS2/S1/tempen,
  digout HiZ); the PL owns live D0 (software or GPIO mirror). Any
  `WRITE(3,…)` from any slot has its data byte replaced by the shadow.
- DSP reset: `dsp_force_h` makes the serializer force bit H on channel
  CONVERTs (cycles 0-31) while the (sw|pin) level is high.
- **Invariant** (from the design doc): only slot 1 is ever whole-command
  replaced; slots 2/3 only get coherent bit substitution.

### Integration (`data_generator_core.sv`)
- Sequencer + override instantiated **inside the core** (all timing signals —
  `cycle_counter`, `state_counter`, `cipo*_data`, `digital_in` — are local).
- Command-source mux at the serializer: `aux_seq_en` is latched once per
  packet; when 0 the datapath is **bit-identical** to `main` (proven, below).
- **Command-echo identity without an `aux_capture` module**: the SPI response
  to the command at cycle C is captured at cycle C+2, so packet word 34
  answers *this* packet's slot-1 command and words 0/1 answer the *previous*
  packet's slot-2/3 commands. Header 64-bit word 2 (32-bit words 4/5) now
  carries `{prev slot-3 echo, prev slot-2 echo, this slot-1 echo, flags,
  digital_in}` — every packet fully labels its own aux payload, self-contained
  under UDP loss, robust to bank swaps. All-zero when the sequencer is off.
- Injection result capture: response lands in `cipo*_data[1]` of the next
  packet → latched to status reg 12 ({cipo1,cipo0} regular words) + an ack
  toggle for the firmware handshake.
- New ctrl regs 22-24 (config / bank-write port / strobes+inject cmd), status
  regs 11-12. `N_CTRL` 22→25, `N_STATUS` 11→13.

### Firmware + host
- `pl_control.c`: bank upload/length/select/**confirm** (the standby-bank
  double-buffer protocol — banks are uploadable DURING acquisition),
  `pl_aux_seq_enable` (disable path clears fast-settle sources first and waits
  a packet — once SEQ_EN drops the override can't reach the chip, so the OFF
  injection must go out beforehand), fast-settle/digout config, and
  inject-based `pl_read_rhd_register`/`pl_write_rhd_register` with the
  ack-toggle handshake.
- `network.c`: `CMD_AUX_WRITE_WORD/BANK_SELECT/SEQ_EN`, `CMD_READ_REGISTER` /
  `CMD_WRITE_REGISTER` (return the 4-byte chip response over TCP),
  `CMD_SET_FAST_SETTLE`, `CMD_SET_DIGOUT`; status struct +12 bytes (98 total).
- `net.py`: mirrored `CMD_*`, RHD command encode/decode, bank upload/swap
  helpers, default slot programs (slot 0 = Reg-3 carrier, slot 1 = accel
  sweep @ 10 kHz, slot 2 = supply/temp/chip-ID/INTAN housekeeping), runtime
  register R/W with echo verification, `aux` command decoding the last
  packet's command echo. **Packet size unchanged** — the echo rides in
  previously-zero header bits.

## Comparison: clean-room v2 vs the `claude/roadmap` attempt

Read after v2 passed its TB: `claude/roadmap:programmable_logic/src/
aux_command_sequencer.sv`, `override_layer.sv`, `aux_capture.sv`, and
`git diff 60d0e89 claude/aux-seq-integration-wip` (the parked integration).

### Where the designs diverge

| Aspect | roadmap attempt | clean-room v2 | Kept |
|---|---|---|---|
| Storage | `(* ram_style = "distributed" *)`, combinational read → 168 LUTs on SLICEM, the exact resource its own post-mortem identified as the congestion mechanism | registered read → BRAM, 1.5 idle tiles, zero SLICEM pressure | **v2** |
| Length record | written to RAM **addr 0** of each bank (commands at 1..63; index init = 1) | dedicated per-bank registers via a `wr_is_length` flag; commands at 0..63 | **v2** (no reserved entry, no 1-based indexing; the addr-0 trick's "pure memory image" upload is not worth the footgun) |
| Advance timing | advances at `packet_start` (start of packet) → **advance-before-use off-by-one**: the first packet after start plays entry *after* the initial index | advances at packet **end** (use-then-advance): first packet plays entry 0 | **v2** |
| Swap → start index | new bank starts at `loop_idx` | new bank starts at **0**, wraps `end→loop` → run-once preamble per bank | **v2** (directly implements the doc's "bank A = config, run once") |
| Idle behavior | none — swaps wait for a `packet_start` that never comes while stopped (PS confirm poll can hang); indices keep stale values | `seq_hold`: swaps apply immediately while idle, indices park at 0 | **v2** |
| Power-on RAM | uninitialized (0 in HW → `CONVERT(0)` if enabled unprogrammed; X in sim) | initialized to `CONVERT(32+slot)` = today's behavior | **v2** |
| Runtime reg R/W | absent (would need bank gymnastics) | one-shot slot-3 injection, frozen index, ack+result capture | **v2** |
| Override structure | per-cycle stage in the serializer path, `RT_SLOT_CYCLE` param | per-packet bundle rewrite, levels latched at `packet_start` | **v2** (see bug below) |
| Reg-3 static bits | host supplies `reg3_static[7:1]` byte, PL owns D0 | (v2 first drafted discrete temp/HiZ config bits) | **roadmap** — adopted into v2: simpler encoding, and differential-temperature stepping later = host rewrites the byte at runtime |
| Echo / capture | `aux_capture.sv`: generic PIPE-deep delay line pairing every result with its origin (284 FFs), alignment flagged as "must verify, Intan's is empirically tuned" | alignment analysis: word 34 = this packet's slot-1 result, words 0/1 = prev packet's slot-2/3 → echo is **3 registers in the core**, no module | **v2** (the "intricate alignment" dissolves once you state which packet each result lands in; verified on the serialized wire in sim) |
| Sequencer location | wrapper (Verilog) instantiates it, ports threaded into the core | inside the core, status out via 2 ports | **v2** (signal locality; wrapper stays thin) |

### A real bug found in the prior override layer

`fs_inject` is set at `packet_start` (state 0 of cycle 0) and cleared **one
clock later** — but its replacement mux requires `cycle_counter == 32`, which
occurs ~2560 clocks later. The two conditions can never overlap: **the
fast-settle injection could never fire on hardware.** (The night log honestly
marked the override "behavior NOT verified" — correctly.) v2's
latch-per-packet + combinational-rewrite structure makes this class of bug
impossible: the latched decision is valid for the entire packet by
construction, and the integration TB checks the injected word on the
serialized COPI wire.

### Also fixed along the way (affects any xsim work on this repo)

The core's idiom `logic name = expr;` is a **continuous assignment to Vivado
synthesis but a one-time static initializer to xsim** (LRM semantics) — in
simulation those signals stick at X and the whole datapath sits idle. That is
why the first identity-TB run "passed" vacuously (both cores idle) and TEST 2
caught it. All such declarations are now `wire name = expr;` (same netlist,
correct sim semantics); the TB run-script applies the same transform to the
baseline core it extracts from git.

### Verdict

The roadmap attempt's *spec-level* ideas were sound (they came from the same
design doc), and its `reg3_static` interface was adopted. Its *implementation*
carried five latent functional defects (off-by-one start, no-idle-swap hang,
uninitialized RAM, dead fast-settle injection, and the storage choice that its
own post-mortem identified as the congestion trigger). The clean-room redo +
compare was worth it: none of those would have been visible in a diff-review
of one implementation alone.

## Decisions taken (with rationale) / still open

- **2 banks/slot** (doc says "≥2, 2–4"): the double-buffer protocol needs
  exactly active+standby; more banks = more addr bits with no protocol win.
- **64 entries/bank** (doc: N≈30): a full 35-command program fits with slack;
  storage is BRAM so depth is nearly free.
- **Bank write port = 3 control registers + toggle strobes**, not the doc's
  memory-mapped AXI BRAM windows: uploads are ~35 words and rare; this avoids
  new AXI ports / BD address-map churn / extra CDC surface entirely.
- **Fast-settle injection point = slot 1 replacement** (the doc's
  Slot-1-only invariant), resolving ROADMAP's OPEN question: a GPIO fast
  settle *replaces* slot 1's command on transition packets; slots 2/3 (accel,
  housekeeping) are never perturbed. Slot 1's default program is a
  `WRITE(3,…)` carrier, so what's sacrificed on a transition packet is one
  digout refresh — the next packet restores it.
- **Temperature: single-point** (fixed tempS bits in `reg3_static`).
  Differential stepping later = host rewrites `reg3_static` in sync with slot
  3's `CONVERT(49)` — no PL change needed.
- **DSP reset = level semantics** (host controls pulse duration); the chip
  resets the filter of each channel converted with bit H while high.
- Impedance testing: deferred to its own epic (swap-in bank fits the design).

## Needs human / hardware / datasheet confirmation

1. **On-hardware validation** of the whole feature (no board attached here):
   `aux_demo` → `aux` echo decode, supply/temp values plausible, chip-ID reads
   return 1/2/4, fast settle visibly clamps amplifiers on a scope/recording,
   `auxout` follows `digout gpio <pin>`.
2. **Echo alignment on real silicon**: the word-34 / words-0-1 result mapping
   is exactly the existing 2-command pipeline (same as the hardcoded
   `convert_cmd_sequence` comment "remember 2 sample delay"), verified in sim
   against the datapath — but a one-time hardware check (read `READ(40..44)`
   = 'INTAN' via slot 3 and match echoes) is cheap and definitive.
3. **First-packet echo staleness**: words 0/1 of the first packet after START
   answer the previous run's last two commands; `echo_valid` (flag bit 4) is 0
   for that packet. Host code ignores it; OpenEphys plugin (Epic F) must too.
4. **Fast-settle pulse duration** is host-side policy (datasheet: ~2.5/fH,
   e.g. 250 µs at 7.5 kHz upper cutoff ≈ 8 packets) — nothing enforces it in
   the PL; document in user workflow.
5. `validator`/`net.py` were not exercised against live UDP (board absent);
   syntax + struct sizes verified.

## Addendum 2026-06-12 — hardware wedge root-caused: AXI-Lite write deadlock

First on-hardware session (via the OpenEphys plugin tooling on
`ephys-socket@claude/aux-test-tooling`): connect, rescan, and streaming all
worked, but the AUX SEQ action **hard-wedged core 0** at `CMD_AUX_BANK_SELECT`
-- serial console silent mid-handler (after 16 successful bank-upload
commands), no exception, no TCP RST, power-cycle required. `net.py aux_demo`
on the same image worked -- but it never sends a bank select and paces
commands at Python speed.

Root cause (sim-proven, `sim/axi_lite_write_tb.sv`): the original
`axi_lite_registers` write FSM toggled `awready`/`wready` independently
against their own valids and required all four ready/valid signals high in
one cycle to accept. If the interconnect asserts AWVALID and WVALID **one
cycle apart** -- legal, and traffic-pattern dependent -- the two readys
oscillate in anti-phase forever: the write is never performed, BVALID never
asserts, and the ARM core stalls mid-store on the AXI-GP port. The TB shows
skew ±1 deadlocks (and the master meanwhile believes both channels
handshook); skew 0/±2 happen to align. Latent since the file was written;
the plugin's microsecond back-to-back command burst is what finally hit the
alignment.

Fix (`c64574d`): joint accept -- AWREADY/WREADY asserted together, only when
both valids present and no response pending (explicitly AXI-compliant), plus
an `~rvalid` guard on ARREADY. TB: 65 checks PASS across skews -2..+2,
interleaved read/write bursts (the aux upload pattern), readbacks.

Debug breadcrumbs around every AXI access in the aux path are on the branch
as `bc75343` (marked DEBUG, revert after hardware validation).
